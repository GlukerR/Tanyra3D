# Дизайн v2 — умный оптимизатор GLB/glTF

Проектирование второй версии `glb_web_optimize`: вместо слепой цепочки CLI-команд — система «анализ → решение → безопасная оптимизация → проверка → отчёт». ТЗ сформулировано Александром 2026-07-16 (промпт сохранён в этом файле по разделам).

## Общая стратегия

**Ключевая смена архитектуры.** v1 — Python-обёртка над CLI-командами: каждая команда применяется всегда, вслепую, без анализа конкретного файла. v2 — Node-скрипт на **SDK glTF-Transform** (`@gltf-transform/core` + `@gltf-transform/functions` + `@gltf-transform/extensions`): документ загружается в память как граф объектов, каждый меш/материал/атрибут доступен программно — можно смотреть, решать и менять точечно.

**Принцип «проверил → сделал → доказал»:** каждая операция состоит из трёх фаз — (1) анализ: правда ли эти данные не нужны; (2) применение: только если анализ дал однозначный ответ, иначе — предупреждение в отчёт; (3) валидация: инварианты не нарушены (число треугольников, валидность материалов, целостность иерархии).

**Порядок конвейера** (важен, как и в v1):

```
загрузка (.glb И .gltf+bin+текстуры)
→ снимок метрик «до» (inspect)
→ структурная чистка сцены (dedup, prune)
→ чистка геометрии (висящие вершины, вырожденные треугольники, weld)
→ чистка атрибутов вершин (COLOR_n, лишние TEXCOORD_n — с проверкой использования)
→ валидация материалов (битые ссылки, неиспользуемые сэмплеры)
→ объединение (join/flatten — опционально)
→ текстуры → KTX2 (кроме уже-KTX2)
→ сжатие геометрии (meshopt/draco)
→ снимок метрик «после» + отчёт + safety-проверки
```

## 1. Текстуры → KTX2 из любого формата

- SDK видит MIME каждой текстуры: `texture.getMimeType()` → `image/webp`, `image/png`, `image/jpeg`, `image/ktx2`.
- **Уже KTX2 → пропустить** (в v1 этого нет: uastc перекодирует повторно, лишняя потеря).
- WebP/JPEG → декодировать в PNG через `sharp` (без потерь: те же пиксели, другой контейнер) → отдать toktx. Это уже реализовано в v1.3 шагом `png`, в v2 — то же, но только для текстур, которым это реально нужно.
- **Разные слоты — разные настройки** (в v1 всё кодируется одинаково):
  - `normalTexture` и `occlusionRoughnessMetallic` — обязательно UASTC (ETC1S портит нормали) + флаг линейного цветового пространства;
  - `baseColorTexture`/`emissiveTexture` — UASTC level 2 (качество) или ETC1S (если важнее вес), sRGB;
  - настройки — в `config.json` рядом со скриптом: уровни, rdo, zstd, per-slot переопределения.
- Правильные sRGB/linear-флаги при кодировании — критичны: перепутанное цветовое пространство «выцветает» или «пережигает» модель.

## 2. Чистка геометрии

- **Висящие (orphan) вершины** — есть в аксессорах, но не адресуются ни одним индексом. Убираются компактированием примитива (в свежих версиях `@gltf-transform/functions` есть `compactPrimitive()`; если версия старее — собственный проход: собрать множество используемых индексов, перестроить аксессоры). Не влияет на рендер вообще — рисуются только индексированные треугольники, но вес и VRAM уменьшаются.
- **Вырожденные треугольники** — треугольник, у которого два или три индекса совпадают (нулевая площадь). Встроенной команды в glTF-Transform нет — собственный проход по индексным аксессорам: `(a==b || b==c || a==c)` → выкинуть тройку. Запускать ПОСЛЕ weld (сварка как раз и порождает вырожденные).
- **Дубли вершин** — `weld()` (уже в v1). В v2 добавить контроль: сравнить число треугольников до/после — weld не должен его менять.
- **Неиспользуемые данные** — `prune()` подчищает всё, на что нет ссылок: узлы, меши, материалы, текстуры, изображения, аксессоры, bufferViews, буферы. `dedup()` — схлопывает дубли ресурсов (две одинаковые текстуры → одна).

## 3. Чистка атрибутов вершин (с проверкой использования!)

- **Вершинные цвета (`COLOR_0`, `COLOR_1`...)**. По спецификации glTF COLOR_0 умножается на baseColor — просто так удалять нельзя, вид изменится. Безопасная логика:
  1. Если все значения COLOR_0 равны (1,1,1,1) — атрибут «пустой», умножение ни на что не влияет → удалять безусловно;
  2. Если цвета реально раскрашены — по умолчанию НЕ удалять, а вынести в отчёт: «найден рабочий vertex paint, удаление изменит вид; форсировать флагом `--strip-vertex-colors`». Флаг — для случая Александра, когда покраска вершин заведомо мусорная из Blender.
- **Лишние `TEXCOORD_n`**. Пройти по всем материалам меша и всем текстурным слотам (включая слоты расширений KHR_materials_clearcoat, sheen, transmission и т.д.) — у каждой привязки текстуры есть индекс UV-канала (`texCoord` в TextureInfo, плюс возможный `KHR_texture_transform` со своим texCoord). Собрать множество реально используемых каналов → неиспользуемые удалить. **Подводный камень:** если удалён TEXCOORD_0, а TEXCOORD_1 используется — каналы надо перенумеровать и обновить все ссылки в материалах, иначе файл сломается.
- Прочие опциональные атрибуты (TANGENT без normal map, JOINTS/WEIGHTS без скина) — тот же принцип: доказать неиспользование → удалить, не доказано → отчёт.

## 4. UV-каналы — что защищать

Не удалять канал, если на него ссылается ХОТЬ ЧТО-ТО: baseColor, normal, occlusion (классика — AO/лайтмапы на TEXCOORD_1), emissive, metallicRoughness, любой слот из расширений материалов. Проверка не по «есть ли текстура в материале», а по конкретному индексу texCoord каждой привязки.

## 5. Валидация материалов

- Ссылки на удалённые ресурсы → чинятся автоматически самим SDK (граф не даёт повиснуть указателю) + финальный `prune`.
- Неиспользуемые сэмплеры/параметры → `prune`.
- Дополнительно: `palette()` из functions — если много материалов, отличающихся только цветом-константой, склеивает их в один материал с крошечной текстурой-палитрой (меньше draw calls). Включать опционально — меняет структуру материалов.

## 6. Оптимизация сцены

`dedup` + `prune` (+ опционально `flatten`, `join`, `instance()` для повторяющихся мешей). Уже есть в v1; в v2 — с отчётом «что именно удалено/склеено, сколько байт сэкономлено».

## 7. Safety-проверки (после всех операций)

1. **Структурная валидация** — прогнать результат через официальный `gltf-validator` (npm `gltf-validator`): 0 ошибок = файл валиден по спецификации.
2. **Инварианты** — сравнение до/после: число видимых треугольников не изменилось (если simplify не разрешён); анимации/скины/morph targets на месте (если были); иерархия узлов валидна.
3. **Визуальная идентичность** — честный ответ: автоматический пиксельный скриншот-дифф требует headless-рендера (three.js + puppeteer) — тяжёлая отдельная подсистема. Практический компромисс v2: инварианты + валидатор автоматически, глаза — gltf.report / свой 3D Viewer. Скриншот-дифф — кандидат в v3.
4. Файлы с ошибками любой фазы — не сохраняются в output (как в v1), причина — в отчёт.

## 8. Отчёт

По каждому файлу — `output/имя.report.md` (+ строка-резюме в консоль):

- найденные проблемы (висящие вершины: N, вырожденные треугольники: N, пустой COLOR_0, неиспользуемый TEXCOORD_1, дубли текстур...);
- выполненные операции и что пропущено с причиной («COLOR_0 раскрашен — не удалён, см. --strip-vertex-colors»);
- размер файла до/после, geometry/texture в байтах;
- **VRAM до/после** — из `inspect()`: gpuSize текстур (это главная метрика для слабых устройств);
- draw calls (число примитивов) до/после;
- предупреждения.

## Часто упускаемые возможности (кандидаты, по желанию)

- `quantize()` — понижение точности атрибутов (позиции в int16 и т.п.), почти бесплатный вес; уже частично делает meshopt;
- `resample()` — пересэмплирование анимационных кривых без визуальных изменений;
- `sparse()` — разреженные аксессоры для morph targets;
- `palette()` — склейка «одноцветных» материалов (см. п.5);
- `instance()` — GPU-инстансинг повторяющихся мешей (столы/стулья в интерьерах!);
- KHR_texture_transform — атлас мелких текстур (ручная работа, в автомат не брать).

## Крайние случаи

- `.gltf` с внешними файлами (bin, текстуры рядом) — SDK читает связку автоматически, выход всегда упаковывать в единый `.glb`;
- модель уже с Draco/Meshopt на входе — раскодировать при загрузке (SDK умеет при зарегистрированных расширениях+декодерах), оптимизировать, закодировать заново;
- текстуры уже KTX2 — не перекодировать (см. п.1);
- COLOR_0 с реальной покраской — не трогать без флага (см. п.3);
- несколько сцен в одном файле — обрабатывать все, не только сцену 0;
- точечные/линейные примитивы (POINTS/LINES) — не прогонять через треугольные проходы (вырожденность, weld) без проверки режима примитива.

## План реализации

1. `package.json` + `optimize2.mjs` — каркас: загрузка, inspect, отчёт (без оптимизаций) — убедиться, что метрики читаются;
2. перенос v1-цепочки на SDK (dedup/prune/flatten/weld/join + meshopt/draco);
3. кастомные проходы: вырожденные треугольники, orphan-вершины, COLOR_n-анализ, TEXCOORD-анализ с перенумерацией;
4. KTX2-фаза с per-slot настройками и пропуском уже-KTX2;
5. gltf-validator + инварианты + отчёты;
6. обкатка на реальных моделях (роутер, дом, столы) — сравнение с v1 по весу/VRAM/draw calls.

v1 (`optimize.py`) остаётся рабочим инструментом, пока v2 не обкатан.
