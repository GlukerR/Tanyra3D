# Идеи по бизнес-модели — glb_web_optimize

> Заметки для будущего. Сейчас фокус — ядро + профили платформ. Это длинный хвост стратегии.

---

## 1. Переориентировать SaaS на Processing API

Не «облачный рабочий стол с командными фичами», а **API-as-a-service**:

- Клиент отправляет GLB через API → получает оптимизированный файл + отчёт.
- Встраивается в чужие пайплайны автоматически — без GUI, без регистрации команды.
- E-commerce платформа подключает API к workflow загрузки 3D-каталога и платит за каждый обработанный файл.
- Это точная аналогия **Cloudinary**, но для 3D-ассетов.

Почему это лучше чем «веб-интерфейс с платными командными фичами»: платёжеспособные B2B-клиенты (средние e-commerce, AR/VR стартапы, игровые студии) покупают автоматизацию, а не интерфейс.

---

## 2. Интеграции раньше облака

Каждая интеграция создаёт lock-in не через ограничение функций, а через встраивание в workflow:

- **GitHub Action** — разработчик добавляет один шаг в CI, больше не думает об оптимизации вручную.
- **Blender Plugin** — художник оптимизирует прямо из Blender перед экспортом.
- **Shopify App** — автоматическая обработка 3D-моделей при загрузке в магазин.

После этого SaaS/API продаётся проще: люди уже зависят от инструмента.

---

## 3. Корпоративные членства / Foundation model (план Б)

Если рынок окажется слишком нишевым для SaaS — Blender Foundation как ориентир:

- Корпоративные членства от компаний, которые встраивают инструмент в продукты (Unity, Khronos-партнёры, платформы e-commerce).
- Автоматические субсидии за использование в коммерческих продуктах.
- Не исключает SaaS — может работать параллельно.

---

## 4. Реальная платёжеспособная аудитория

Не indie-художники (не платят за SaaS), а:

- Средние e-commerce компании с 3D-каталогами (Shopify-мерчанты с AR-превью).
- Игровые студии среднего размера.
- AR/VR стартапы.
- Платформы, которые принимают 3D-контент от пользователей и хотят его автоматически нормализовать.

---

## 5. Риск «AWS tax»

Если инструмент станет популярным — AWS/GCP/Azure могут добавить его в Marketplace. Apache-2.0 это не остановит.

Защита не в лицензии, а в:
- **Скорости разработки** — мы знаем продукт лучше.
- **Качестве managed service** — SLA, support, мониторинг.
- **Сетевых эффектах** — если в облаке хранятся ассеты и история версий, переехать болезненно.
- **Интеграциях** — 50 студий с подключённым webhook не пойдут разбираться с AWS Marketplace.

---

## 6. Честная финансовая траектория

- Первые 2–3 года: нулевой доход.
- Потом: enterprise-продажи через прямой контакт (не self-serve).
- Потом: processing API как масштабируемый источник дохода.

Self-serve SaaS приносит деньги только при тысячах активных пользователей. До этого — пустая инфраструктура.

---

## Итог в одном предложении

Desktop — всегда бесплатный; деньги делает **Processing API** (Cloudinary-модель) + корпоративные членства + интеграции, которые создают lock-in через workflow.

---

## Enterprise-угол: инструмент как онбординг команды

Объясняющий слой — это не только UX, но и аргумент для B2B: инструмент **сокращает время онбординга джуна в студии**. Вместо передачи «племенных знаний» пайплайна изустно (экспортируй FBX, примени триангуляцию, сожми KTX2 — без объяснения зачем) — новый сотрудник учится, пока работает, потому что каждое решение объяснено. Это измеримая ценность (время адаптации), усиливает раздел про корпоративные членства выше.
