# Выпуск: два канала — стабильный и предварительный

Раньше выпуск был один на всех: любой тег `v*` становился «последней версией», и большая
кнопка «Скачать» в README вела на него же. Значит проверенное и непроверенное выходило
одной дверью, и выложить свежую сборку на пробу было нельзя — она сразу становилась той
версией, которую скачивает случайный человек.

Теперь дверей две. Ничего нового ставить не пришлось: у GitHub эта возможность есть
изначально, у релиза есть признак «предварительный» (pre-release).

## Как выбирается канал

**По имени тега, а не отдельной кнопкой.** Дефис в номере означает предварительную
версию — это правило самой схемы номеров (SemVer, §9), его же понимают все инструменты.

| Тег | Канал | Что видит человек |
|---|---|---|
| `v0.2.3` | стабильный | Отметка **Latest**. Кнопка «Скачать» в README ведёт сюда |
| `v0.2.3-beta.1` | предварительный | Отметка **Pre-release**. Кнопка «Скачать» его не показывает |

Ставить галочку руками не нужно и нельзя забыть: `.github/workflows/release.yml` смотрит
на имя тега сам.

## Почему кнопка «Скачать» не ломается

Ссылка в README — `…/releases/latest`. GitHub на этом адресе отдаёт последний **не**
предварительный выпуск: предварительные он пропускает. То есть человек, пришедший за
программой, продолжает получать проверенное, даже если сверху лежат три пробные сборки.

Кому нужна свежая — идёт на страницу `…/releases`, там видны обе, и предварительная
подписана.

## Номера предварительных версий

`0.2.3-beta.1`, `0.2.3-beta.2`, … — то есть «то, что станет 0.2.3». Выпуск стабильной
`v0.2.3` закрывает эту серию.

Номер в `package.json` при этом тоже с дефисом: он попадает в имена файлов
(`Tanyra3D-0.2.3-beta.1-windows-x64.exe`) и в строку версии в самой программе — человек
должен видеть по установленному файлу, пробная у него сборка или нет.

## Порядок выпуска

1. Поднять номер в `package.json` (кто и какую цифру имеет право двигать — Правило 0).
2. `npm install --package-lock-only` — номер лежит в lock-файле в двух местах, и сторож
   `tests/electron-config.test.mjs` их сверяет. Пропустить этот шаг — красный CI.
3. Полный набор проверок (Правило 7) — **после** подъёма номера, не до.
4. Коммит, `git push` ветки, зелёный `test.yml`, слияние в `main`.
5. Тег и его отправка — `git tag v0.2.3-beta.1 && git push origin v0.2.3-beta.1`.
   Сборка установщиков под тремя платформами запускается тегом.

Пункты 4 и 5 требуют прямого слова Александра — отправка на удалённый репозиторий
красная линия (Правило 0).

## Чего здесь НЕТ

**Самообновления.** Программа не проверяет, вышла ли новая версия, и не скачивает её:
`electron-updater` не установлен, `latest.yml` не собирается. Каналы разделены только на
странице выпусков. Появится самообновление — у него будет свой канал в тех же терминах
(`latest` / `beta`), менять схему тегов не придётся.

**Отдельной ветки под стабильное.** Ветка одна — `main`; канал определяет тег, а не
ветка. Понадобится чинить старую стабильную версию, пока `main` ушёл вперёд, — тогда и
появится ветка вида `release/0.2.x`, раньше она пустая работа.
