# Выпуск: два канала — проверенный и свежий

Раньше выпуск был один на всех: любой тег `v*` становился «последней версией», и большая
кнопка «Скачать» в README вела на него же. Значит проверенное и непроверенное выходило
одной дверью, и выложить свежую сборку на пробу было нельзя — она сразу становилась той
версией, которую скачивает случайный человек.

Теперь дверей две. Ничего нового ставить не пришлось: у GitHub эта возможность есть
изначально, у релиза есть признак «предварительный» (pre-release).

## Главное правило: Latest ставит человек, а не машина

**Любой выпуск рождается предварительным.** Всегда, независимо от имени тега.

Причина простая и её стоит помнить. Зелёные тесты говорят о коде. Они не говорят, что
установщик ставится, что программа открывается, что видно оба вьюпорта. В момент, когда
сборка сходит с конвейера, её не запускали **ни разу ни на одной машине** — и конвейер не
может этого знать в принципе.

Поэтому отметку **Latest** снимает человек, руками:

> Releases → нужный выпуск → **Edit** → снять галочку **Set as a pre-release** → при
> необходимости поставить **Set as the latest release** → **Update release**.

Делается это **после** установки и проверки. Пересборки не требуется: галочка меняет
отметку у тех самых файлов, которые и проверяли — не у их пересобранной копии.

Правило введено 2026-08-15 после замечания Александра: «как ты считаешь, что релиз
стабильный, если мы его даже на ПК не проверяли?». До этого канал выбирался по имени
тега, и тег без дефиса становился Latest сам собой.

**Уточнено 2026-08-18: снять отметку может и Клод — по прямому слову Александра, после
того как тот поставил сборку и посмотрел.** Правило требует, чтобы ПРОВЕРЯЛ человек, а не
чтобы он лично кликал: галочку можно переставить через `gh release edit`, и на 0.2.5 так и
вышло — «версия работает, значит можно её выгружать на гите. сделай это сам». Без такого
слова отметка не трогается: молчание проверкой не является, а конвейер по-прежнему не
знает, открывалось ли окно.

## Что тогда значит дефис в теге

Дефис (`v0.2.4-beta.1`) по SemVer §9 означает предварительную версию. У нас он теперь
помечает выпуск, который повышать до Latest **не собираются вовсе** — пробную сборку под
конкретную проверку. На поведение конвейера он не влияет: предварительны и такие, и
обычные.

| Тег | Что означает | Кто снимет отметку |
|---|---|---|
| `v0.2.4` | обычный выпуск, кандидат в проверенные | Александр, после установки |
| `v0.2.4-beta.1` | пробная сборка под конкретную проверку | никто, так и останется |

## Почему кнопка «Скачать» не ломается

Ссылка в README — `…/releases/latest`. GitHub на этом адресе отдаёт последний **не**
предварительный выпуск: предварительные он пропускает. То есть человек, пришедший за
программой, продолжает получать проверенное — даже если сверху лежат три свежие сборки,
которых ещё никто не открывал.

Кому нужна свежая — идёт на страницу `…/releases`, там видны обе, и предварительная
подписана. Ссылка на неё стоит прямо под кнопкой «Скачать».

## Номера версий

Третье число (`0.2.3 → 0.2.4`) поднимает Клод, когда прогнан полный набор и красных нет.
Второе и первое (`0.3.0`, `1.0.0`) — только по слову Александра. Подробности и причина —
`CLAUDE.md`, Правило 0.

Номер в `package.json` попадает в имена файлов (`Tanyra3D-0.2.4-windows-x64.exe`) и в
строку версии внутри программы — по установленному файлу видно, что именно стоит.

## Когда поднимать номер

**На каждом мёрже в `main`** — слово Александра 2026-08-19: «когда делаешь мёрж всегда
следующую версию ставь». Не «когда накопится», не «перед выпуском»: слитая работа без
номера превращает установщик во враньё — по имени файла и по строке версии внутри
программы нельзя понять, что именно у человека стоит.

Мёрж, не тронувший ничего, кроме документов, — единственное исключение: там менять нечему.

## Порядок выпуска

1. Поднять номер в `package.json`.
2. `npm install --package-lock-only` — номер лежит в lock-файле в двух местах, и сторож
   `tests/electron-config.test.mjs` их сверяет. Пропустить этот шаг — красный CI.
   (`npm version <номер> --no-git-tag-version` делает оба шага сразу.)
3. Полный набор проверок (Правило 7) — **после** подъёма номера, не до.
4. Коммит, `git push` ветки, зелёный `test.yml`, слияние в `main`.
5. Тег и его отправка — `git tag -a v0.2.6 && git push origin v0.2.6`. Сборка
   установщиков под тремя платформами запускается тегом.
   **Описание выпуска ставить отдельной командой** — `gh release edit vX.Y.Z --notes …`.
   На сообщение тега не рассчитывать: 2026-08-26 на `v0.2.13` оно в тело выпуска не
   попало вовсе, GitHub подставил свою автосводку «Full Changelog».
6. **Александр ставит сборку у себя и смотрит.**
7. Только теперь — снять отметку «pre-release» в интерфейсе GitHub.

**Пункты 1–5 идут подряд и БЕЗ ОСТАНОВКИ — разрешение выдано вперёд.** Александр,
2026-08-26: «новый тег всегда. иногда там будет мелкая правка, иногда список больших
выполненных задач. есть законченная версия? тогда делай мёрж и отправлять тег. всегда.
это должно быть правилом». Спрашивать «выпускать?» на каждой версии не надо: вопрос уже
отвечен, и отвечен раз навсегда.

**Объём — не критерий.** Мелкая правка и десяток крупных задач выкладываются одинаково.
Критерий один: версия закончена и проверена (пункт 3 зелёный). Копить «до кучи» нельзя —
именно так и появилась дыра с пропущенным `v0.2.8`.

Разрешение распространяется ТОЛЬКО на эту цепочку. `push` веток, `--force`, отправка чего
угодно помимо `main` и тега версии — по-прежнему красная линия (Правило 0), нужно его
слово.

**Пункт 7 остаётся за ним** и даётся ПОСЛЕ установки и осмотра сборки: проверяет человек,
кликнуть может Клод (уточнение 2026-08-18 выше). Это не формальность — конвейер не знает,
открылось ли окно.

## Описание выпуска — КОРОТКИЙ СПИСОК ПО-АНГЛИЙСКИ, и всё

**Введено Александром 2026-08-23** в два захода. Сперва про объём: «такой пелёнки к
каждому релизу делать не нужно. очень кратко список изменений и всё». Затем про остальное:
«вот это тоже не нужно и всегда пиши на английском все релиз листы на гите» — про строки
с итогом прогона и про установщики.

Формат: **только список изменений, на английском**. Строка на изменение, отвечает на один
вопрос — *что теперь другое*. И больше в описании нет ничего.

```
- OBJ import. Materials are read from the neighbouring `.mtl`; the `usemtl` split is preserved.
- Model size is now the whole delivery — the file plus its neighbours.
- README and docs now describe FBX and OBJ import.
```

Чего в описании НЕ пишем, и каждое из этого там уже побывало:

- разбор причин, «где легко ошибиться», цитаты, таблицы;
- **итог прогона** («4317 прошло, 0 упало») — это наша внутренняя кухня;
- **список установщиков и оговорка про Windows** — оговорка стоит в `README.md`, разделе
  Status, а файлы сборки видны на самой странице выпуска.

**Почему по-английски, хотя язык проекта русский.** Правило 0 требует русского для ответов,
сводок, коммитов и документации — то есть для того, что читаем мы. Страница выпусков читается
не нами: репозиторий открытый, и приходят на него откуда угодно. Это единственное
исключение из языкового правила, и оно ровно одно.

**Почему коротко, хотя причины решений мы ценим.** Читатель выпуска и читатель кода — разные
люди с разными вопросами. Пришедшему за программой нужно знать, стоит ли обновляться;
«почему мы сделали именно так» ему мешает. Место для причин есть и не одно: шапки модулей,
комментарии тестов, `.claude/CONTEXT.md`, сообщения коммитов. Там они и живут.

**Сообщение тега тоже короткое и тоже английское.** Оно попадает в описание выпуска
автоматически, и длинное приходится переписывать вручную. Заодно снимается ловушка:
обратные кавычки в `git tag -m` съедает оболочка, и `.mtl` пропал прямо из описания 0.2.11.

## Чего здесь НЕТ

**Самообновления.** Программа не проверяет, вышла ли новая версия, и не скачивает её:
`electron-updater` не установлен, `latest.yml` не собирается. Каналы разделены только на
странице выпусков. Появится самообновление — у него будет свой канал в тех же терминах
(`latest` / `beta`), менять схему тегов не придётся.

**Отдельной ветки под стабильное.** Ветка одна — `main`; канал определяет отметка на
релизе, а не ветка. Понадобится чинить старую проверенную версию, пока `main` ушёл
вперёд, — тогда и появится ветка вида `release/0.2.x`, раньше она пустая работа.
