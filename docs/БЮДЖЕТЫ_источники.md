# Откуда взяты числа бюджетов

> Каждое число в `profiles/*.json` должно иметь ссылку на документацию платформы.
> Пользователь видит бюджет как приговор своей модели и верит ему — число без
> источника здесь не число, а наша догадка с уверенным лицом.
>
> Сверка проведена 2026-07-29. **Результат: подтверждается меньшинство чисел.**

---

## Главная оговорка: модель — это не сцена

Почти вся документация платформ говорит о **кадре целиком**: сколько треугольников и
отрисовок может позволить себе приложение за один кадр. Наш бюджет — про **один файл**.

Meta пишет «500–1000 отрисовок на кадр». Это на всё приложение: на комнату, на аватары,
на интерфейс. Взять это число как лимит для одной модели — ошибка категории, а не
консервативная оценка.

Поэтому числа из документации **нельзя копировать напрямую**. Либо мы находим источник,
который говорит именно про отдельный ассет (как Shopify и Khronos 3D Commerce), либо
честно признаём, что доли от кадрового бюджета мы придумали сами.

---

## Подтверждено первоисточником

| Платформа | Параметр | Значение | Источник |
|---|---|---|---|
| Shopify | размер файла, цель | **4 МБ** | [3D model standards checklist](https://help.shopify.com/en/partners/resources/creating-3d-models/3d-model-standards-checklist) — «The total file size should be about 4 MB» |
| Shopify | размер файла, потолок | **15 МБ** (выше — Shopify пережимает сам) | [Creating 3D models for merchants](https://help.shopify.com/en/partners/resources/creating-media/3d-models/creating-3d-models/3d-modeling-checklist) |
| Shopify | текстуры | **до 2048×2048** | тот же checklist — «shouldn't be larger than 2048 x 2048 px» |
| Shopify | материалы | **один**, если не требуется иначе | тот же checklist |
| Quest | статичные треугольники | **50 000 на глаз на вид** (консервативная цель) | [Android Development / mobile performance](https://developers.meta.com/horizon/documentation/unity/unity-mobile-performance-intro/) |
| Quest / PC VR | отрисовки | **500–1000 на кадр** — на приложение, не на модель | [Guidelines for VR Performance Optimization](https://developers.meta.com/horizon/documentation/native/pc/dg-performance-guidelines/) |

### Что нашлось важного, но не числом

**Meta для WebXR не даёт числовых целей вообще.** [WebXR Performance Best
Practices](https://developers.meta.com/horizon/documentation/web/webxr-perf-bp/) — только
качественные советы: один источник света, KTX2/Basis для текстур, сортировка непрозрачных
объектов. Прямая цитата документа: рекомендации не гарантии, проверять надо на железе.

Это ровно наш случай — Quest мы целим через браузер, а не через Unity.

## НЕ подтверждено — стоит в профилях без источника

| Профиль | Параметр | Стоит | Проблема |
|---|---|---|---|
| threejs | `triangles: 100000` | | В `notes` профиля указан Khronos 3D Commerce. Проверить не удалось: PDF 1.0 отдаёт 403, [руководство 2.0](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md) раздел publishing targets ещё не заполнило |
| threejs | `drawCalls: 50` | | Источника нет |
| threejs | `vramMB: 128` | | Источника нет |
| threejs | `fileMB: 10` | | Источника нет |
| shopify | `triangles: 150000` | | Shopify **не называет** число треугольников — только «как можно меньше» |
| shopify | `drawCalls: 25` | | Shopify об отрисовках не пишет вовсе |
| shopify | `vramMB: 100` | | Источника нет |
| shopify | `fileMB: 15` | | Число верное, но это **потолок**, а рекомендация — 4 МБ. Показывать потолок как цель значит поощрять худший допустимый вариант |
| quest | все четыре | | Числа Meta — на кадр и на приложение; как поделить их на одну модель, документация не говорит |
| mobile | все пять | | Источника нет ни на одно |

Единственное косвенно подтверждённое из этого списка — пример в [блоге
Khronos](https://www.khronos.org/blog/khronos-gltf-asset-auditor): профиль веб-AR с
целями «до 3 МБ, до 30 000 треугольников, текстуры до 1024». Это **пример** возможного
профиля, а не рекомендация Khronos.

---

## Что с этим делать

1. **Не показывать неподтверждённые числа как границы.** Пользователь не отличит
   выверенное «Shopify: 4 МБ» от придуманного «Quest: 8 МБ», а доверять будет одинаково.
2. **Показывать измеренное, а не приговор.** «В модели 1.2 млн треугольников, 340 отрисовок»
   — факт. «Слишком тяжёлая» — суждение, которое надо заслужить источником.
3. **Каждое число в профиле снабдить полем со ссылкой.** Тогда неподтверждённое видно
   сразу — по пустому полю, а не по памяти того, кто его вписал.
4. **Открытый вопрос, который надо решить до чисел:** одна платформа — не один бюджет.
   Сайт только для ПК и сайт с мобильными дают разные пороги при одном и том же Three.js.
   Ось профиля — «движок + класс устройства», а не просто «движок».
