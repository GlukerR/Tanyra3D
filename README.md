# Tanyra3D

**Оптимизатор 3D-моделей для веба, который объясняет, что он сделал и почему.**

Вы кладёте `.glb`, отмечаете нужные галочки, получаете модель меньшего веса — и отчёт
человеческим языком: что нашлось, что применилось, что осталось нетронутым и по какой
причине. Ничего не происходит молча.

> Статус: **0.0.8**, ранняя разработка. Ядро и веб-интерфейс работают, набор из 549
> тестов зелёный. Публичного релиза ещё не было, API может меняться.

---

## Чем отличается от `gltf-transform optimize`

Готовая команда `gltf-transform optimize` по умолчанию включает упрощение полигонов и
уменьшение текстур. Для каталога товаров или портфолио это неприемлемо: модель, за
которую заплатили, приходит обратно огрублённой.

Здесь другой принцип — **всё выключено по умолчанию**. Пустой список оптимизаций означает,
что файл прочитается, проверится и запишется без единого изменения. Каждая оптимизация
включается отдельно и сопровождается честным описанием: что она делает, обратима ли,
теряются ли данные, и нужен ли декодер на стороне сайта.

Второе отличие — **проверка результата**. После обработки движок сверяет структуру модели
со снимком, сделанным до сжатия: треугольники, вершины, вызовы отрисовки, скины, анимации,
morph-таргеты, набор атрибутов. Если что-то разошлось — файл **не записывается**, а отчёт
объясняет, что именно сломалось. Лучше не отдать результат, чем отдать испорченную модель,
поломку которой не видно на глаз.

## Что умеет

| Оптимизация | Что делает | Потери |
|---|---|---|
| **safe** | Дедупликация материалов и текстур, удаление неиспользуемых данных и UV-каналов, сварка совпадающих вершин, вырезание вырожденных треугольников | нет |
| **join** | Объединение мешей — меньше вызовов отрисовки | нет, но части перестают быть отдельными объектами |
| **instance** | Повторяющиеся меши → `EXT_mesh_gpu_instancing` | нет |
| **meshopt** / **draco** | Сжатие геометрии. Число полигонов не меняется — данные пакуются компактнее | нет |
| **ktx2** | Текстуры в KTX2: ETC1S для цвета, UASTC для нормалей и данных. Экономит и загрузку, и видеопамять | почти незаметные |
| **resample** | Прореживание избыточных кадров анимации | нет |
| **strip-colors** | Удаление вершинных цветов | да, только явным включением |

`meshopt`, `draco`, `ktx2` и `instance` требуют подключить соответствующий декодер на
целевом сайте — интерфейс помечает это значком.

## Установка

Нужен [Node.js](https://nodejs.org/) 18 или новее.

```bash
git clone <адрес репозитория>
cd glb_web_optimize
npm install
```

Для KTX2-сжатия текстур дополнительно нужен
[KTX-Software](https://github.com/KhronosGroup/KTX-Software/releases) — программа сама
найдёт `ktx` в `PATH` или в `C:\Program Files\KTX-Software\bin`. Без него все остальные
оптимизации работают, а KTX2 честно сообщит, что инструмент не найден.

## Запуск

### Веб-интерфейс

```bash
npm start
```

Откроется `http://localhost:3210`. Перетащите модель, выберите платформу, отметьте
оптимизации, нажмите **Build Optimized Model**. Слева исходник, справа результат, между
ними — цифры «было → стало» и отчёт.

Всё работает локально. Модели никуда не загружаются.

### Командная строка

```bash
node optimize2.mjs                          # пресет: safe + meshopt + join
node optimize2.mjs draco                    # то же, но Draco вместо Meshopt
node optimize2.mjs --keep-parts             # без объединения мешей
node optimize2.mjs --ktx2                   # добавить сжатие текстур
node optimize2.mjs --dry-run                # полный анализ и отчёт, ничего не записывая
node optimize2.mjs --passthrough            # ничего не применять, только проверить
node optimize2.mjs --strip-vertex-colors    # удалить и раскрашенные вершинные цвета
```

Обратите внимание: **в командной строке без флагов применяется пресет**, а не passthrough —
так сложилось исторически, и поведение сохранено, чтобы не ломать существующие скрипты.
Программный интерфейс и веб-интерфейс по умолчанию не делают ничего.

Файлы берутся из `input/`, результат и отчёт `имя.report.md` кладутся в `output/`.

### Программный интерфейс

```js
import { optimizeFile, listRules, VERSION } from './optimize2.mjs';

const result = await optimizeFile('model.glb', {
  advancedFeatures: ['safe', 'draco'],
  outDir: 'output',
});

console.log(result.status);              // 'ok' | 'fail'
console.log(result.metrics.before, result.metrics.after);
console.log(result.applied);             // что реально применилось
console.log(result.validation);          // результаты проверок
```

Полный контракт — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §4b.

## Как устроено

Обработка идёт пятью фазами: **анализ → план → применение → проверка → отчёт**.

Каждая оптимизация — самостоятельное правило со своими метаданными: насколько серьёзна
находка, доказуемо ли безопасно исправление, обратимо ли оно, какие данные затрагивает,
после каких других правил должно выполняться. Движок сам строит порядок и сам решает,
что применять: до уровня «незаметно глазу» включительно автоматически, потери — только
явным включением.

Ядро (`core/`) не знает про glTF. Всё, что относится к формату, живёт в аддоне
(`addons/gltf/`). Это сделано ради второго формата, а не ради красоты.

- [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — устройство ядра, контракты API
- [`docs/EXTENDING.md`](docs/EXTENDING.md) — как добавить своё правило
- [`docs/MISSION.md`](docs/MISSION.md) — зачем проект существует
- [`docs/ROADMAP.md`](docs/ROADMAP.md) — что дальше

## Тесты

```bash
npx vitest run
```

Тесты интеграционные: настоящие модели через настоящий пайплайн, без моков.

В репозитории лежат десять небольших моделей (около 1 МБ), сделанных специально для
проверки — намеренно «грязный» куб, сетка связанных дубликатов, morph-таргеты, вершинные
цвета, уже сжатый вход, заведомо битый файл. Их достаточно, чтобы набор был зелёным сразу
после клонирования. Тесты, которым нужны более тяжёлые модели, помечаются пропущенными с
указанием причины.

У каждой модели рядом лежит `.md` с описанием: что внутри, что она проверяет и какие
цифры измерены.

## Ограничения

- **Вьюер не проигрывает анимацию.** Модель показывается в позе покоя. Сама анимация при
  оптимизации сохраняется и проверяется, но убедиться в этом глазами в интерфейсе пока
  нельзя — скачайте результат и откройте в [glTF Viewer](https://gltf-viewer.donmccurdy.com/).
- **Проверка анимаций и скинов — счётная.** Движок следит, чтобы клипы и скины не
  пропали, но не сравнивает их содержимое покадрово.
- **`meshopt` на персонажах с морф-таргетами** может испортить скиннинг. Пайплайн это
  обнаруживает и отказывается писать файл; используйте `draco`.
- Пакетная обработка есть только в командной строке; в веб-интерфейсе — по одной модели.
