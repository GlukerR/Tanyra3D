# Tanyra3D — оптимизация GLB для веба

> Название приложения — **Tanyra3D**. Репозиторий/пакет — `glb-web-optimize`.

Кладёшь любое число `.glb` в `input/` → запускаешь → забираешь из `output/` модели, готовые к выгрузке на веб. Полигоны не удаляются, разрешение текстур не меняется.

## Для чего создан

Пайплайн подготовки GLB-моделей к вебу (просмотрщик Three.js, Tilda). Ручная цепочка команд gltf-transform для каждой модели — долго и легко ошибиться в порядке шагов. Скрипт прогоняет всю цепочку автоматически по всем файлам сразу.

## Почему сделан именно так

- **Не используется готовая команда `gltf-transform optimize`** — она по умолчанию включает `simplify` (упрощение полигонов) и `texture-resize` (снижение разрешения текстур). По требованию Александра модель и текстуры не должны терять качество — поэтому цепочка собрана вручную только из безопасных шагов.
- **Порядок шагов фиксированный** (важно!): сначала структура (`dedup → prune → flatten → weld → join → reorder`), потом текстуры (KTX2), сжатие геометрии — строго последним. Menять порядок нельзя: например, weld до draco улучшает сжатие, а draco до join сломает пайплайн.
- **Перед KTX2 текстуры декодируются в PNG** (шаг `png`) — рабочий формат экспорта текстур у Александра WebP, а toktx читает только PNG/JPEG. Декодирование без потерь: пиксели те же, просто другой контейнер; итог всё равно KTX2.
- **KTX2/UASTC для текстур** — выбор Александра: экономит и скачивание, и видеопамять (VRAM), near-lossless. Флаги `--level 2 --zstd 18` без RDO — RDO сознательно не используется, он вносит дополнительные потери.
- **join включён по умолчанию** — модели статичные, взрыв-схемы не нужны (решение Александра, 2026-07-16). Для интерактивных моделей есть флаг `--keep-parts`.
- **Выбор кодека геометрии аргументом**: Meshopt по умолчанию (быстрее декодируется в браузере, лучше для анимаций), Draco по запросу (минимальный вес). Оба поддерживаются просмотрщиком 3D Viewer.
- **toktx ищется и вне PATH** — в `C:\Program Files\KTX-Software\bin`. Галочка «Add to PATH» при установке не критична.
- Сжатие геометрии (Draco/Meshopt) — это НЕ упрощение: число полигонов не меняется, данные вершин просто пакуются компактнее.

## Требования и запуск

1. **Node.js LTS** (уже стоит — используется для Vite/Three.js).
2. **Один раз запустить `install.bat`** (двойной клик) — поставит:
   - `@gltf-transform/cli` глобально через npm;
   - KTX-Software v4.4.2 (скачает официальный установщик ~6 МБ с GitHub Khronos и запустит).
3. Положить `.glb` в `input/`.
4. Запустить:

```
python optimize.py                    # Meshopt (по умолчанию, рекомендуется)
python optimize.py draco              # Draco (минимальный вес файла)
python optimize.py --keep-parts      # не объединять меши (интерактив/взрыв-схема)
python optimize.py --no-ktx          # не трогать текстуры
```

Логи: `[РАБОТА]` с прогрессом по шагам, `[ГОТОВО] имя.glb: 89.40 МБ → 12.10 МБ (−86%)`, `[ПРОПУСК]` если файл уже в output/, `[ОШИБКА]` с хвостом сообщения gltf-transform.

Проверка результата: перетащить файл в [gltf.report](https://gltf.report/) или открыть в своём 3D Viewer.

## Важно для просмотрщика

Модели с KTX2-текстурами требуют в Three.js-просмотрщике `KTX2Loader` + basis-транскодер (`ktx2Loader.detectSupport(renderer)`), иначе модель загрузится без текстур. Draco и Meshopt просмотрщик уже поддерживает. Подробности — [[3D Viewer — Three.js просмотрщик GLB]].

## Итерации, ошибки и тупики

- **2026-07-16, v1.** Создан в облачной сессии Claude. Ограничение среды: облачная песочница не имела сетевого доступа к GitHub/npm (403), поэтому бинарники toktx доставить напрямую не удалось — решение: `install.bat`, который качает установщик на самом ПК через встроенный в Windows `curl.exe`. Версия KTX-Software v4.4.2 и имя файла установщика проверены по официальному релизу Khronos на дату создания. Winget-пакета KTX-Software не существует (проверено) — поэтому прямое скачивание с GitHub releases.
- **2026-07-16, v1.1.** Первый запуск install.bat: gltf-transform встал, а KTX-Software — нет (диагностика diag.bat: нет ни в Program Files, ни в PATH). Причина: batch не проверял результат скачивания и установки — установщик мог не запуститься или UAC отклонён, а скрипт шёл дальше. Решение: отдельный `install_ktx.bat` — curl с `--fail`, проверка размера скачанного файла (>1 МБ), тихая установка NSIS-флагом `/S` (один запрос UAC, без окон мастера), явная проверка результата с поиском toktx.exe по Program Files.
- **2026-07-16, v1.2.** install_ktx.bat мгновенно закрывался без вывода. Причина — классические грабли cmd: закрывающая скобка в тексте `echo` внутри блока `if (...)` ломает парсинг всего блока, batch умирает синтаксической ошибкой до первой паузы. Было: `echo ... (%KTX_SIZE% байт).` внутри блока. Решение: переписан вообще без скобочных блоков — только `goto :метки`, в текстах echo нет ни одной скобки. Правило на будущее: в .bat не использовать скобки в echo внутри if/for-блоков, а лучше строить логику на goto. После исправления установка прошла успешно — toktx подтверждён в `C:\Program Files\KTX-Software\bin`.
- **2026-07-16, v1.3.** Первый боевой прогон (роутер 3.25 МБ) выявил два дефекта. (1) Текстуры остались WebP вместо KTX2: Александр экспортирует текстуры из Blender сразу в WebP, а toktx читает только PNG/JPEG — шаг uastc молча пропускал WebP с кодом 0. Решение: перед uastc добавлен шаг `png` (декодирование текстур в PNG без потерь — команда проверена по документации gltf-transform.dev/cli). (2) Падение на финальном `shutil.move`: rename сообщил «файл не найден», хотя итоговый файл появился — на папке vault работает слой синхронизации Cowork, rename там ненадёжен. Решение: последний шаг пайплайна пишет сразу в `output/имя.glb`, переименований больше нет; плюс проверка существования файла после каждого шага и уникальные имена temp-файлов.
- Известное ограничение: если у модели текстуры уже в KTX2, повторный прогон `uastc` перекодирует их заново (лишняя потеря). Уже обработанные файлы пропускаются по имени в `output/`, так что при обычном использовании это не проблема.

## v2 — умный оптимизатор (optimize2.mjs)

Реализован 2026-07-16 по дизайну [[ДИЗАЙН_v2_умный_оптимизатор]]. Отличия от v1: работает через SDK glTF-Transform (анализ каждого файла, а не слепая цепочка), принимает и `.glb`, и `.gltf`; пропускает уже-KTX2 текстуры; удаляет пустые вершинные цвета (все белые — автоматически; раскрашенные — только с флагом `--strip-vertex-colors`); удаляет неиспользуемые UV-каналы и атрибуты (prune с проверкой по материалам); вырезает вырожденные треугольники и висящие вершины; после обработки — safety-проверки (треугольники/анимации/скины на месте, gltf-validator Khronos) и отчёт `output/имя.report.md` с метриками до/после, включая VRAM.

Установка (один раз): двойной клик `install_v2.bat` — ставит npm-зависимости в папку скрипта (SDK, draco, meshopt, sharp, валидатор). toktx уже стоит.

Запуск:
```
node optimize2.mjs                        # Meshopt + текстуры mixed (по умолчанию)
node optimize2.mjs draco                  # Draco
node optimize2.mjs --keep-parts          # не объединять меши
node optimize2.mjs --no-ktx              # не трогать текстуры
node optimize2.mjs --uastc               # ВСЕ текстуры в UASTC (макс. качество, тяжёлый файл)
node optimize2.mjs --dry-run             # полный анализ и отчёт, ничего не записывая
node optimize2.mjs --strip-vertex-colors # удалить и раскрашенные вершинные цвета
```

**Обкатка v2 (2026-07-16, тест в VM моста на модели «роутер», без KTX2-фазы):** конвейер прошёл целиком, 0 ошибок. Найдено и вычищено то, ради чего v2 задумывался: неиспользуемый `TEXCOORD_1`, неиспользуемый `COLOR_1`, полностью белый `COLOR_0` (удалён как безопасный). Файл 3.25 → 1.01 МБ (−69%) ещё до KTX2. Все safety-проверки зелёные, gltf-validator — 0 ошибок. Грабли переноса: перезапись существующего файла через device_commit_files обрезает его до старой длины — большие файлы на устройство переносить через base64 + device_bash; Windows-установленный sharp не грузится в Linux VM (платформенные бинарники) — для VM-теста заглушался в изолированной копии.

**Логи (v2.2):** каждый запуск пишет полный лог в `logs/run_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.log` — всё из консоли + стеки ошибок + версии инструментов. Логи старше 30 дней скрипт удаляет сам при старте (константа `LOG_KEEP_DAYS`). Назначение: Claude читает их через файловый мост для диагностики и патчей без пересказа ошибок вручную.

**Грабли Windows (2026-07-16):** вызов `gltf-transform.cmd` через shell ломался ошибкой «"node" не является командой» — двойной слой кавычек в .cmd-обёртке npm. Решение: скрипт находит JS-вход CLI через package.json глобальной установки и вызывает его напрямую текущим node (`process.execPath`), без .cmd и shell.

**Ещё двое граблей Windows (2026-07-16, найдены по логу ошибки):** (1) gltf-transform CLI v4 требует бинарник `ktx`, а не `toktx` — оба идут в комплекте KTX-Software 4.4.2, скрипт теперь ищет `ktx.exe`; (2) переменная окружения на Windows называется `Path`, а не `PATH` — код, добавлявший каталог KTX в `childEnv.PATH` по точному ключу, создавал дубликат, который затирал системный путь у дочернего процесса (симптом: «"where" не является командой»). Теперь ключ ищется без учёта регистра.

v1 (`optimize.py`) остаётся рабочим как запасной вариант.

## v3 — движок + правила (рефактор optimize2.mjs)

Реализован 2026-07-17 по чертежу [[РЕФАКТОР_v3_движок-правил|docs/РЕФАКТОР_v3_движок-правил.md]] (файл с тех пор перемещён в `_work/` как архивный) (большая архитектура — `docs/ARCHITECTURE.md`). Поведение и запуск НЕ изменились (`node optimize2.mjs`, те же флаги) — изменилась форма кода:

- **Массив `RULES`** — каждое действие пайплайна (dedup, prune, вершинные цвета, weld, вырожденные треугольники, висящие вершины, join, KTX2, сжатие) — самостоятельный объект-правило с `meta` (id, категория, `severity`, `fixSafety`, `runAfter`, `touches`, `enabled`), `analyze`, `canFix`, `fix`. Добавить проверку = дописать один объект, движок не трогается.
- **Движок из 5 фаз** вместо монолитного `processFile`: АНАЛИЗ → ПЛАН (canFix + политика безопасности + топологическая сортировка по `runAfter`) → ПРИМЕНЕНИЕ → ВАЛИДАЦИЯ → ОТЧЁТ.
- **Две оси**: `severity` (насколько плохо) и `fixSafety` (доказуемость безопасности: provable/numeric/perceptual/lossy). Автофикс — до `perceptual` включительно (KTX2/UASTC — осознанный выбор), `lossy` — только явным флагом (`--strip-vertex-colors`).
- **Новый отчёт**: Найдено (проблемы) → Пропущено (с причиной) → Применено → Валидация → Оценка улучшений.
- **Валидация расширена**: к проверкам v2 (треугольники/анимации/скины/gltf-validator) добавлены bounding box в пределах эпсилон, целостность сцен, резолв материалов. При провале любого инварианта `.glb` НЕ записывается (v2 записывал всегда); отчёт с ❌ пишется в любом случае.
- Запись через `writeBinary` в память → валидация байтов → один `writeFileSync`; переименований нет (грабли v1.3 не повторяются).

**Проверка эквивалентности (2026-07-17, роутер 1.glb):** итоговый `.glb` **байт-в-байт совпал** с выводом v2 (SHA256 `CEFB4109…`), те же находки (TEXCOORD_1, COLOR_1, белый COLOR_0, 3 текстуры → KTX2), валидатор 0 ошибок. Ветки флагов проверены прогоном `--no-ktx --keep-parts --strip-vertex-colors` (3.25 → 1.01 МБ, −69% — совпадает с обкаткой v2). Копия v2 и эталонный вывод — в `_work/` (и навсегда в git-истории); после подтверждения `_work/` можно удалить.

**Версионирование (с 2026-07-17, схема Александра):** папка — git-репозиторий, версия в `package.json` + git-теги. Отсчёт: итерации разработки — `0.0.x` (v1=0.0.1, v2=0.0.2, рефактор «движок+правила»=**0.0.3** — текущая); когда всё устроит и версия станет нормально рабочей → **0.1.0** (первая версия); продукт, готовый к опенсорсу → **1.0.0**. Модели (`input/`, `output/`), логи и `node_modules` не версионируются (.gitignore); `_work/` — рабочая папка для временных файлов и бэкапов, тоже вне git.

**0.0.4 (2026-07-17) — первый большой прогон (22 модели) и три исправления по его ошибкам.** 7 моделей завернула валидация v3 — и все три причины были настоящими: (1) счёт треугольников/draw calls был «по объектам-мешам» и прыгал, когда dedup схлопывал одинаковые меши в один-на-многих-узлах, а flatten разворачивал обратно — теперь счёт по узлам сцены (инвариантен к инстансам; v2 имел ту же слепоту, но его нестрогая проверка молчала); (2) у `r 250.glb` входное Draco-расширение оставалось на документе и каждая запись файла молча пережимала геометрию заново с потерями (−85…−461 треугольников за roundtrip) — теперь входное сжатие KHR_draco/EXT_meshopt снимается при загрузке и перекодируется один раз (граничный случай из ARCHITECTURE §6 «не стекировать»); (3) `общий.glb` пришёл с 38 ошибками валидатора в исходнике — теперь при ошибках на выходе проверяется вход, блокируют запись только НОВЫЕ ошибки, унаследованные помечаются ℹ с примерами. После исправлений: 22/22 модели проходят, 0 ошибок.

**0.0.5 (2026-07-17) — режим текстур mixed (ETC1S+UASTC) и `--dry-run`.** По роадмапу («выбор ETC1S/UASTC — ближайшая практическая доработка») и решению Александра:

- **Текстуры по умолчанию кодируются смешанно**: цветовые (baseColor, emissive и пр.) → **ETC1S** quality 255 — в разы легче UASTC и в файле, и в VRAM; data-текстуры (нормали, occlusion, roughness/ORM) → **UASTC** `--level 2 --zstd 18` — ETC1S мылит нормали и даёт ступеньки на roughness. Классификация автоматическая по слотам материала (`listTextureSlots`), кодирование двумя проходами CLI с `--slots`-глобами. Прежний режим «всё UASTC» — флаг `--uastc`. В отчёте перечислено, какая текстура каким кодеком и почему.
- **`--dry-run`** — первый режим Analyze из роадмапа: все пять фаз прогоняются в памяти (цифры в отчёте точные), но `.glb` не записывается; отчёт — отдельным файлом `имя.dryrun.report.md`, существующие результаты не затираются и не пропускаются.
- Замечание по партии «промышленных» моделей: у металла часто нет цветовых текстур (только normal+roughness), там mixed совпадает с uastc — вес файла определяют data-текстуры. Следующий рычаг для них — `--max-texture-size` из роадмапа.

**0.0.6 (2026-07-17) — первая анимированная модель (прогон 60 моделей).** «Ноутбук.glb» — rigged-модель (кости + анимация крышки) — валидация остановила запись: «скины потеряны». Разбор показал: flatten/join glTF-Transform анимационно-аккуратны (меши остались под своими костями, слились только соседи под одним родителем — безопасно), а «потерянный» скин был **пустышкой**: у мешей нет JOINTS/WEIGHTS, деформаций не было, анимация работает вращением нод; prune удалил его правомерно. Исправление: инвариант считает только **действующие** скины (привязанные к вершинам через JOINTS_0), удаление пустышек фиксируется в отчёте как находка. Настоящая потеря действующего скина по-прежнему блокирует запись. Итог прогона: 60/60, 0 ошибок.

Функции `listPlatforms()`, `planFor(platformId)`, `explainResult(RunResult, platformId)` переводят технические результаты в объяснения для пользователя. Контракт §4c.

- **Веб-интерфейс (server.mjs + ui/):** браузер-сервер на чистом `node:http` (без новых зависимостей). Поток: drag&drop GLB → выбор платформы → кнопка «Обработать» → live-статус фаз (SSE) → результат (было/стало + улучшения + проверка бюджетов) → скачать модель. Дизайн по макету stitch_3d_asset_optimizer_ui/ (тёмный верстак). 3D-превью — заглушка, появится позже. Проверено с кириллическими именами файлов.

- **Запуск:** `npm start` → браузер на http://localhost:3210. Результаты (модели) скачиваются кнопкой, серверные копии в `_web/` (вне git).

Следующие шаги (не в 0.0.8): новые правила (oversized textures, ORM packing, instancing) — по одному в `RULES`; **умное объединение мешей** (идея Александра, 2026-07-17): join применять по условиям (нет анимации + один текстурный сет), не флагом; вьюер 3D (before/after, wireframe, heat map); batching в UI; батч-обработка серверная; TypeScript/монорепо — по `ARCHITECTURE.md` §7.
